# Chudnovsky π calculation — serial benchmark

## Objective

Compute the decimal expansion of **π** using the rapidly converging Chudnovsky series, with historical results generated by a **single-core binary-splitting Python implementation** scheduled through Slurm. This workload demonstrates high-precision arithmetic and job scheduling; **it is not an MPI or multi-node parallel calculation**.

## Files in this folder

- [`Chudnovsky-Results/digits/`](Chudnovsky-Results/digits/) — ten archived files from 100,000 through 1,000,000 digits, in 100,000-digit increments; each file contains an execution header and line-wrapped digits.
- [`Chudnovsky-Results/slurm_commands.md`](Chudnovsky-Results/slurm_commands.md) — historical submission records invoking `~/jobs/chud/chud_fast.py`.
- [`chud.py`](chud.py) — existing **serial iterative/Decimal** implementation; **not** the program recorded as producing the historical binary-splitting outputs.
- [`chud_fast.py`](chud_fast.py) — **newly reconstructed** standard binary-splitting version added for reproducibility. It was not recovered from the original job directory and must **not** be described as the exact source of archived jobs.

## Archived results

The files report 100k–1M digits. For example, the 100,000-digit file identifies `node01`, Slurm job `28`, and a reported `0.8 seconds` from the historical single-core run. Larger jobs and their numeric output are preserved in the same folder. The digit prefixes across archived files have been checked against the longest result, but shared prefixes alone are **not independent mathematical verification** of the complete one-million-digit output.

## Running a fresh job

From a cloned checkout on the admin node, prepare the historical working path (the original `slurm_commands.md` uses `~/jobs/chud`):

```bash
REPO="$(git rev-parse --show-toplevel)"
mkdir -p "$HOME/jobs/chud"
cp "$REPO/Chudnovsky's Pi Calculation/chud_fast.py" "$HOME/jobs/chud/"
cd "$HOME/jobs/chud"
python3 chud_fast.py 1000
# For a Slurm serial job:
sbatch -N1 --ntasks=1 --job-name=chud1000 --output=chud-1000-%j.out \
  --wrap='cd "$HOME/jobs/chud" && python3 chud_fast.py 1000'
```

`chud_fast.py` writes `pi_<digits>_digits.txt` in the current working directory. Run small tests before attempting hundreds of thousands of digits. A generated file should be kept separate from the historical archived record unless independently verified and labeled as a new run.

## Algorithm at a glance

The Chudnovsky formula yields roughly 14 decimal digits per term. Binary splitting combines integer products in a divide-and-conquer tree before one final arbitrary-precision division and square-root calculation, avoiding repeated high-precision division at every series term. Runtime depends strongly on Python version, integer arithmetic, machine speed, and precision.

## Limitations and next steps

The **exact original `chud_fast.py`, original Slurm stdout, and a consolidated performance table were not included in the supplied archive**. The new implementation closes the runnable-code gap *for future work*, not the historical provenance gap. To establish historical reproducibility, recover the original program and `chud-*.out` from the admin node if they still exist, and record `python3 --version`, CPU, Slurm job ID, and precise time for each new run.
