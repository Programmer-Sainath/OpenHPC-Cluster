## Storage

The live `/etc/exports` is generated by Warewulf:

```text
/home 192.168.10.0/255.255.255.0(rw,sync)
/opt 192.168.10.0/255.255.255.0(ro,sync,no_root_squash)
```

`exportfs -v` **effectively** reported `/home` as `rw,sync,root_squash` and `/opt` as `ro,sync,no_root_squash`; both subnet restricted. The distinction between the literal generated file and effective NFS options matters.

On **all four nodes**, `findmnt` verified `/home` mounted `warewulf:/home` by **NFSv4.2 read-write** with address `192.168.10.2`. `/opt` was **not** an NFS mount at observation time; the default Warewulf fstab resource sets `noauto,nofail,ro` for it. Compute `df` showed shared `/home` ≈40G total, ≈2.4G used, and per-node ephemeral `rootfs` ≈7.1G (not an additional persistent disk).

## Time synchronization

Admin Chrony config included `pool 2.rocky.pool.ntp.org iburst`, `allow 192.168.10.0/24`, `local stratum 10`, `makestep 1.0 3` and `rtcsync`. `timedatectl` reported `NTPSynchronized=yes`; `chronyc tracking` cited `time.cloudflare.com`, **stratum 4**, system time **0.000218232 seconds slow**, `Leap status: Normal`. The active NTP peer can change naturally. Compute `chronyd` services were active, but per-node offset/NTPSynchronized were **not measured**.

## Firewall (security review required)

- Runtime `public` zone: `enp2s0` campus-facing; default zone also `public`. Active services: `cockpit`, `dhcp`, `dhcpv6-client`, `nfs`, `ssh`, `tftp`; open TCP ports `9873`, `6817–6818`.
- Runtime `trusted` zone: `enp3s0` cluster LAN, `target: ACCEPT`.
- Permanent `public` zone had **no explicit interface association** in `firewall-cmd --permanent --zone=public --list-all`; permanent `trusted` zone included `enp3s0`. This output alone does not prove that public-zone interface persistence is broken; other connection settings may assign zones.
- Cluster-management services appearing in `public` deserve **prompt review with the school's network/IT supervisor**. The output alone does not establish Internet reachability or compromise. No firewall mutations are supplied in this repository.

## Limits of the evidence

This snapshot does **not** independently verify reboot resilience, an all-node MPI runtime test after the cleanup, physical network isolation, diskless image contents or integrity, source of Munge key distribution, actual cgroup containment, compute Chrony offsets, or any claim that full installation can be reproduced from these documents without adaptation.
